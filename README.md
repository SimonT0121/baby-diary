# 寶寶日記 v1.2

手機用的日記工具。照片和文字**全部存在手機瀏覽器裡**，不經過任何伺服器。

---

## 一、部署（只做一次）

1. 到 GitHub 開一個新 repo，例如 `baby-diary`，設為 Public（GitHub Pages 免費版需要 Public）。
2. 把這 6 個檔案上傳到 repo 根目錄：
   - `index.html`
   - `manifest.webmanifest`
   - `sw.js`
   - `icon-192.png`、`icon-512.png`、`icon-maskable.png`
3. Settings → Pages → Source 選 `Deploy from a branch`，branch 選 `main` / `(root)`，存檔。
4. 等一兩分鐘，網址會是 `https://你的帳號.github.io/baby-diary/`。

**必須是 https，service worker 才會運作。GitHub Pages 本來就是 https，不用另外設定。**

## 二、手機設定（兩支手機各做一次）

1. 用 **Chrome** 打開上面的網址。
2. 右上角選單 → **安裝應用程式**（或「加到主畫面」）。
3. 從主畫面的圖示開啟，登記孩子的名字和生日。
4. 第一次開啟時程式會要求「持久儲存」權限，允許它。

**一定要從主畫面圖示開啟，不要每次都從 Chrome 開網址。** 只有安裝過的狀態，系統才比較不會清掉資料，分享選單裡也才會出現「寶寶日記」。

## 三、日常用法

- **一次放很多張**（最順的路徑）：Google 相簿裡選好幾張 → 分享 → 寶寶日記。或按右下角 ＋ →「選照片」。
- 照片會**依拍攝日期自動分篇**：同一天的合成一篇，不同天分開。確認畫面上可以改每組的日期、刪掉不要的照片、選是哪個孩子，再按「全部存起來」。
- 讀不到拍攝日期的照片會單獨成一組、排在最上面，先放今天，請確認日期。
- 文字之後再補：時間軸上方的「✎ 待補文字」可以只列出還沒寫的篇，一篇一篇補。
- 只想寫字不放照片：＋ →「只寫文字」。
- 卡片**長按**可以快速編輯或刪除。
- 刪除的日記會在「最近刪除」放 30 天。

## 四、輸出 PDF（列印或做紙本相簿）

設定 → 輸出 PDF → 選日期範圍、孩子、版面 → 產生 PDF → 列印畫面上方的印表機選「**儲存為 PDF**」→ 按下載圖示。

- **每篇一頁**：適合做相簿，每篇獨立一頁。
- **連續排**：省紙，篇與篇之間用細線分隔。
- 排列由舊到新，像一本書的順序。每篇有日期、當時月齡、照片、文字。
- 照片一次超過 150 張，手機可能會很慢，建議一次輸出一兩個月。

## 五、備份（最重要）

設定 → 備份 → 等打包完成 → 按「存到手機」。檔案會存進手機的「下載」資料夾，再打開「雲端硬碟」App → ＋ → 上傳 → 選這個檔案。

「直接分享到其他 App」這顆按鈕在部分手機上可以直接送到雲端硬碟，但 Chrome 常常不允許分享 zip，失敗時會自動改成存到手機。

- 超過 14 天沒備份，時間軸最上面會出現提醒。
- 換手機時：新手機安裝好 app → 設定 → 從備份還原 → 選那個 zip。
- 還原是「只補缺的」，已經存在的篇數不會被覆蓋，所以重複還原不會產生重複資料。

## 六、運作規則

| 項目 | 規則 |
|---|---|
| 照片壓縮 | 長邊縮到 1400px、JPEG 品質 0.75，一張約 200KB。原圖留在手機相簿，不重複存 |
| 日期來源 | 讀照片 EXIF 的 `DateTimeOriginal` |
| 批次分篇 | 同一批照片依拍攝日期分組，一組一篇；確認畫面可改日期 |
| 單篇編輯加照片 | 在既有日記裡加照片不會拆篇，日期仍取最早那張 |
| 讀不到日期 | 預設今天，日期欄會標示，可手動改 |
| 跨日提醒 | 一篇的照片跨超過一天時，會顯示提示，但不強制拆篇 |
| 月齡 | 未滿 1 個月顯示天數；未滿 2 歲顯示「X 個月 Y 天」；之後顯示「X 歲 Y 個月」 |
| 重複照片 | 用拍攝日期加原始檔案大小比對，只提示不阻擋 |
| 草稿 | 文字每隔約 1 秒自動存進 localStorage，下次開啟會問要不要接著寫 |

## 七、這個工具不做什麼

- **不做兩支手機同步。** 資料在誰的手機就只在誰的手機。兩個人都要寫，只能各寫各的，再靠 zip 互相匯入（會變成兩份各自獨立的日記，不會合併成一份）。
- **不備份到雲端。** 備份是你自己按的，按了才有。沒按就沒有。
- **不讀 Google 相簿的相簿結構。** 它只接系統分享選單送進來的照片檔，看不到你的相簿、標籤或人臉分類。
- **不保留原始畫質。** 壓縮是不可逆的，備份檔裡也是壓縮後的版本。要留原圖請依賴 Google 相簿本身。
- **不處理影片。**
- **不做搜尋、標籤、分享頁面。** 用一陣子再看缺什麼。
- **舊日記不會自動拆篇。** v1.2 之前一篇多張、跨好幾天的日記維持原樣。要拆的話：編輯那篇、刪掉部分照片，再重新從相簿分享一次。
- **PDF 畫質適合家用列印，不適合專業相簿印刷。** 照片存的是長邊 1400px 的壓縮版，印整頁 A4 大約 170 dpi；專業相簿通常要 300 dpi，要用原圖另外做。
- **PDF 版面不能細調。** 用的是瀏覽器列印功能，字型和分頁由 Chrome 決定。
- **無法保證瀏覽器不清資料。** 「持久儲存」只是降低風險，不是保證。**正式保存以 zip 備份檔為準。**
- **iPhone 支援不完整。** 分享選單不會出現這個 app，也挑不到只存在 Google 相簿雲端的照片。這版是照 Android / Pixel 設計的。

## 八、已驗證項目

交付前在 node + jsdom 環境跑過：月齡計算 8 種邊界（含跨月底、滿兩歲換算）、EXIF 日期解析（有 EXIF／無 EXIF／非照片）、zip 打包與還原往返（系統 `unzip` 可正常開啟）、首次登記 → 新增 → 存檔 → 篩選 → 刪除 → 還原 → 備份的完整流程，批次依日期分組（含同日合併、日期不明、改日期、取消後清照片）、待補文字篩選、PDF 版面產生（排序、封面、欄數、分頁），共 62 項通過。

未驗證、需要在實機上確認的有三件事：

1. 從 Google 相簿分享進來時，照片的 EXIF 是否保留（共享相簿的照片尤其要試）。
2. 分享選單裡是否出現「寶寶日記」（需先安裝到主畫面）。
3. 持久儲存權限是否真的取得（Chrome 開發者工具或多放幾天觀察）。
4. 從主畫面圖示開啟時，按「產生 PDF」能否叫出列印畫面。叫不出來的話，改用 Chrome 瀏覽器直接開網址再輸出（資料是共用的）。

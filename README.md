# 寶寶日記 v1.3

## v1.3 更新了什麼（2026-09-23）

- **Android 返回手勢**：在編輯、內頁、設定裡往回滑，會回上一頁，不會直接關掉 app。在首頁要連滑兩次才離開。
- **備份提醒更誠實**：備份檔存到手機後，會問「上傳到雲端硬碟了沒」。沒按「已上傳」之前，首頁會一直提醒。
- **新增「只備份文字」**：幾十 KB，幾秒完成，可以直接分享到雲端硬碟或寄給自己。照片原圖本來就在 Google 相簿，文字才是這個 app 獨有、救不回來的部分。
- **備份和還原不再吃記憶體**：照片再多也不會因為打包而當掉。
- **還原會比新舊**：同一篇兩邊都有時，留比較新的版本（例如在舊手機補寫過的字）。
- **批次可以拆篇、分孩子**：同一天兩件事時，點選照片 →「拆成另一篇」。有兩個以上孩子時，每篇可以分別選是誰。
- **照片順序改用點的**：編輯時點照片 → 設成封面／往前／往後／移除。
- **時間軸變快**：存照片時同時存一張小縮圖，捲到才載入。舊照片的縮圖會在開啟後背景慢慢補。
- **設定頁新增「診斷資訊」**：app 出問題時按「複製診斷資訊」，貼給維護的人。
- 修正：分享進來的照片若處理到一半失敗，下次開啟會再收一次，不會不見。
- 修正：照片的拍攝日期資訊排在後面時讀不到的問題。

**從 v1.2 升級**：只要把 `index.html`、`sw.js`、`README.md` 三個檔案覆蓋上傳到 GitHub。圖示和 `manifest.webmanifest` 沒有改。手機上的資料不受影響，下次開啟會自動升級。

手機用的日記工具。照片和文字**全部存在手機瀏覽器裡**，不經過任何伺服器。

## 一、部署（只做一次）

1. 到 GitHub 開一個新 repo，例如 `baby-diary`，設為 Public（GitHub Pages 免費版需要 Public）。
2. 把這 6 個檔案上傳到 repo 根目錄：
   - `index.html`
   - `manifest.webmanifest`
   - `sw.js`
   - `icon-192.png`、`icon-512.png`、`icon-maskable.png`
3. Settings → Pages → Source 選 `Deploy from a branch`，branch 選 `main` / `(root)`，存檔。
4. 等一兩分鐘，網址會是 `https://你的帳號.github.io/baby-diary/`。

**必須是 https，service worker 才會運作。GitHub Pages 本來就是 https，不用另外設定。**

## 二、手機設定（兩支手機各做一次）

1. 用 **Chrome** 打開上面的網址。
2. 右上角選單 → **安裝應用程式**（或「加到主畫面」）。
3. 從主畫面的圖示開啟，登記孩子的名字和生日。
4. 第一次開啟時程式會要求「持久儲存」權限，允許它。

**一定要從主畫面圖示開啟，不要每次都從 Chrome 開網址。** 只有安裝過的狀態，系統才比較不會清掉資料，分享選單裡也才會出現「寶寶日記」。

## 三、日常用法

- **一次放很多張**（最順的路徑）：Google 相簿裡選好幾張 → 分享 → 寶寶日記。或按右下角 ＋ →「選照片」。
- 照片會**依拍攝日期自動分篇**：同一天的合成一篇，不同天分開。確認畫面上可以改每組的日期、刪掉不要的照片、選是哪個孩子，再按「全部存起來」。
- 讀不到拍攝日期的照片會單獨成一組、排在最上面，先放今天，請確認日期。
- 文字之後再補：時間軸上方的「✎ 待補文字」可以只列出還沒寫的篇，一篇一篇補。
- 只想寫字不放照片：＋ →「只寫文字」。
- 卡片**長按**可以快速編輯或刪除。
- 刪除的日記會在「最近刪除」放 30 天。

## 四、輸出 PDF（列印或做紙本相簿）

設定 → 輸出 PDF → 選日期範圍、孩子、版面 → 產生 PDF → 列印畫面上方的印表機選「**儲存為 PDF**」→ 按下載圖示。

- **每篇一頁**：適合做相簿，每篇獨立一頁。
- **連續排**：省紙，篇與篇之間用細線分隔。
- 排列由舊到新，像一本書的順序。每篇有日期、當時月齡、照片、文字。
- 照片一次超過 150 張，手機可能會很慢，建議一次輸出一兩個月。

## 五、備份（最重要）

有兩種備份，建議兩種都做：

| | 完整備份 | 只備份文字 |
|---|---|---|
| 內容 | 照片＋文字（zip） | 只有文字和日記結構（txt，幾十 KB） |
| 多久一次 | 兩週一次 | 補完一批文字就傳一次 |
| 怎麼做 | 設定 → 完整備份 → 存到手機 → 雲端硬碟 App 上傳 → 回來按「已上傳」 | 設定 → 只備份文字 → 分享選單選雲端硬碟或 Gmail |

- 完整備份存到手機後，**要按「已上傳」提醒才會消失**。存在手機「下載」資料夾不算備份：手機遺失時它會一起不見。
- 超過 14 天沒完整備份，時間軸最上面會出現提醒。
- 換手機時：新手機安裝好 app → 設定 → 從備份還原 → 選 zip。之後再還原最新的文字備份，補上後來寫的字。
- 還原是「只補缺的」：沒有的篇新增；兩邊都有的篇，留比較新的版本。重複還原不會產生重複資料。
- 只用文字備份還原時，照片會是空白格；之後再還原 zip 就會補上。

## 六、運作規則

| 項目 | 規則 |
|---|---|
| 照片壓縮 | 長邊縮到 1400px、JPEG 品質 0.75，一張約 200KB。原圖留在手機相簿，不重複存 |
| 日期來源 | 讀照片 EXIF 的 `DateTimeOriginal` |
| 批次分篇 | 同一批照片依拍攝日期分組，一組一篇；確認畫面可改日期 |
| 單篇編輯加照片 | 在既有日記裡加照片不會拆篇，日期仍取最早那張 |
| 讀不到日期 | 預設今天，日期欄會標示，可手動改 |
| 跨日提醒 | 一篇的照片跨超過一天時，會顯示提示，但不強制拆篇 |
| 月齡 | 未滿 1 個月顯示天數；未滿 2 歲顯示「X 個月 Y 天」；之後顯示「X 歲 Y 個月」 |
| 重複照片 | 用拍攝日期加原始檔案大小比對，只提示不阻擋 |
| 草稿 | 文字每隔約 1 秒自動存進 localStorage；切到別的 App 時也會存。下次開啟會問要不要接著寫 |
| 縮圖 | 長邊 320px，只給時間軸用，不放進備份（還原後自動重產） |
| 批次拆篇 | 選到的照片變成獨立一篇，日期先沿用原本那組，可再改 |
| 還原合併 | 以每篇的「最後修改時間」比新舊 |

## 七、這個工具不做什麼

- **不做兩支手機同步。** 資料在誰的手機就只在誰的手機。兩個人都要寫，只能各寫各的，再靠 zip 互相匯入（會變成兩份各自獨立的日記，不會合併成一份）。
- **不備份到雲端。** 備份是你自己按的，按了才有。沒按就沒有。
- **不讀 Google 相簿的相簿結構。** 它只接系統分享選單送進來的照片檔，看不到你的相簿、標籤或人臉分類。
- **不保留原始畫質。** 壓縮是不可逆的，備份檔裡也是壓縮後的版本。要留原圖請依賴 Google 相簿本身。
- **不處理影片。**
- **不做搜尋、標籤、分享頁面。** 用一陣子再看缺什麼。
- **拆錯的篇不能在確認畫面併回去。** 可以取消重來，或存好之後編輯。
- **舊日記不會自動拆篇。** v1.2 之前一篇多張、跨好幾天的日記維持原樣。要拆的話：編輯那篇、刪掉部分照片，再重新從相簿分享一次。
- **PDF 畫質適合家用列印，不適合專業相簿印刷。** 照片存的是長邊 1400px 的壓縮版，印整頁 A4 大約 170 dpi；專業相簿通常要 300 dpi，要用原圖另外做。
- **PDF 版面不能細調。** 用的是瀏覽器列印功能，字型和分頁由 Chrome 決定。
- **無法保證瀏覽器不清資料。** 「持久儲存」只是降低風險，不是保證。**正式保存以 zip 備份檔為準。**
- **iPhone 支援不完整。** 分享選單不會出現這個 app，也挑不到只存在 Google 相簿雲端的照片。這版是照 Android / Pixel 設計的。

## 八、給維護的人（Simon）

- **不要在她的手機上開測試版。** 所有 `你的帳號.github.io/任何repo/` 都算同一個網站，共用同一個資料庫。測試版要換掉 `DB_NAME`，或放在別的帳號。同一個 GitHub 帳號下的其他 Pages 工具，也和這個 app 共用儲存空間。
- **改資料欄位時**：`SCHEMA` +1，在 `migrate()` 補一段轉換。`normEntry()` 負責把舊備份補齊欄位。
- **新增 object store 時**：`DB_VER` +1，而且 `sw.js` 的 `onupgradeneeded` 清單要一起補。`sw.js` 開資料庫不指定版本，所以只升版本不會打架。
- **改 `sw.js` 時**：把 `CACHE` 名稱換掉，舊快取才會被清。
- **她回報問題時**：請她到設定頁最下面按「複製診斷資訊」貼給你。
